# 耐久运行记录对账与保护定位 v7

耐久台不产出逐周期向量：控制器只记录每组引脚值（hold）保持了多少个时钟，质检探针按各自的时钟相位、步长和阈值采样。本入口在不展开全程向量的前提下，给出全记录对账、首次保护触发定位，并从同一次连续运行中冻结触发时刻附近的短波形。入口 `logic-replay --soak-check <JSON> --output <JSON>`，与 `--source`、`--campaign`、`--qualify`、`--recover`、`--pack-shard`、`--rollup-shards`、`--audit-transfers` 互斥，不接收 `--approvals`。

## 输入

顶层恰好四个字段：`circuit`、`holds`、`monitors`、`capture`。

- `circuit`：现有 `inputs`/`gates`/`flops`/`outputs` 网表（规则见 [v1 契约](contract.md)），不含向量；触发器最多 8 个，其余网表规则（单驱动、组合环拒绝、三值门语义等）不变。
- `holds`：1..64 项，每项恰含 `id`、`ticks`、`inputs`。`id` 沿用向量 ID 格式且在数组内唯一；`ticks` 为 1..10¹² 的正整数，全部段的时钟总数 `N <= 10^12`。`inputs` 必须给出全部输入端各一个 `"0"`/`"1"`/`"X"`，段内每个时钟都施加该组值。各段按数组顺序从全局时钟 0 起无缝相接，段间不复位、不漏时钟；没有探针采样的时钟触发器也照常更新。
- `monitors`：1..16 项，每项恰含 `id`、`output`、`first`、`through`、`stride`、`expected`、`trip_after`。`id` 在探针数组内唯一；多个探针可引用同一个已声明观测输出。约束 `0 <= first <= through < N`；探针从 `first` 起每隔 `stride` 个时钟采样一次、不超过 `through`（上界本身不必是采样点），跨段不重新定相。`stride` 与 `trip_after` 为 1..10¹² 的整数；阈值大于探针总采样数也合法。`expected` 只能是 `"0"`、`"1"` 或 `"X"`。
- `capture`：恰含 `before`、`after`，各为 0..64 的整数，单位是实际时钟（不是探针采样次数）。

上述整数字段均不接受布尔值；未知字段、重复键、错误类型、越界、重复 ID、非法网表或信号引用一律拒绝。

## 回放语义与对账

完全沿用原回放语义：从网表初值开始，用当前段输入和边沿前状态计算组合输出，同一边沿的全部触发器一起采入下一状态，不能边更新边采样。

- 单个探针只在自己的采样点比较观测输出；实际值与期望严格相等才算通过，期望 `"X"` 要求实际也是 `"X"`，不是通配。
- 探针连续 `trip_after` 次采样失配时，在第 `trip_after` 次失配的时钟触发；该探针的一次匹配即清掉自己的连败。未采样的时钟、其他探针的结果和段边界都不会清连败。
- 保护触发只用于定位证据，不回写、不截断这份已完成的记录；计数覆盖每个探针到期为止的全部采样点。报告同时给出整份记录的总时钟数和最后一个边沿后的完整触发器状态。

长记录不会被展开：每个 hold 内电路状态有限（最多 3⁸ 种），先走到状态重复形成周期轨道，之后任意时钟的边沿前状态、观测输出和边沿后状态都按轨道算术取得；探针采样按周期块批量对账，而不是逐时钟迭代。

## 冻结波形

在全部探针的首次触发时钟中取全局最早者，列出在该时钟首次触发的全部探针 ID（按探针输入顺序），只交付一个围绕它的波形窗口。窗口含触发时钟本身，向前后各取 `capture.before`/`capture.after` 个实际时钟，并裁到 `[0, N-1]`。

逐实际时钟给出：全局时钟 `clock`、所属段 ID `hold_id`、零基段内偏移 `hold_offset`、完整 `inputs`、边沿前全部触发器状态 `state_before_edge`、边沿前观测输出 `outputs`、边沿后全部触发器状态 `state_after_edge`。窗口内未被任何探针采样的时钟也必须交付；窗口起始状态来自该次连续运行本身，不因窗口开始或跨输入段而重新初始化。全程无触发时，触发字段与波形窗口均为 `null`，不交付默认窗口。

## 报告字段契约

`schema_version` 为 7，顶层字段：

- `total_clocks`：整份记录的总时钟数 `N`。
- `monitors`：按探针输入顺序排列的对账数组，每项为 `{id, output, samples, mismatches, trip_clock, streak_start_clock}`；`samples` 为该探针的采样总数，`mismatches` 为失配总数，`trip_clock` 为首次触发时钟、未触发为 `null`，`streak_start_clock` 为导致该次触发的连败起点采样时钟、未触发为 `null`。
- `first_trip_clock`：全部探针首次触发中的全局最早时钟；无触发为 `null`。
- `trigger_monitor_ids`：在 `first_trip_clock` 首次触发的全部探针 ID（输入顺序）；无触发为 `null`。
- `waveform_window`：冻结波形行数组（字段见上）；无触发为 `null`。
- `final_state`：最后一个边沿后的完整触发器状态，键为触发器 ID；无触发器时为 `{}`。
- `summary`：`{total_clocks, monitors, triggered_monitors, total_mismatches, first_trip_clock, window_rows}`，其中 `window_rows` 在无窗口时为 0。

仅重排 JSON 对象的键不改变报告含义或报告数组顺序。

## 校验与失败约定

整个输入在分析前完整校验：未知/缺失字段、重复键与非有限常量、错误类型（含布尔冒整数字段）、越界数量、`through >= N`、重复 ID、非法网表（含组合环、多驱动）或未知信号引用等都拒绝。沿用 ≤8 MB 单文件输入限制、严格 JSON 与同目录临时文件原子硬链接的一次性新建发布；目标路径已存在（包括符号链接）时退出 2，不覆盖、不遗留半份结果。有失配或保护触发是正常分析结果，退出 0 并写完整报告。全程离线，仅用标准库。

## 万亿时钟交接样例与复现

`fixtures/soak/handoff-1e12.json`（由 `tools/generate_soak_handoff.py` 生成）：`q.D = XOR(q, a)`、`q.initial="0"`；A 段 `a="1"` 保持 800000000001 拍，B 段 `a="0"` 保持 199999999999 拍，共 10¹² 时钟。两个探针都看 `q` 并期望 `"0"`，`through=999999999999`：

- 密采样探针从 0 起每拍采样、阈值 2：1000000000000 次采样、599999999999 次失配，首次于 800000000002 触发，连败起点 800000000001。
- 疏采样探针从 1 起每 200000000 拍采样、阈值 4001：5000 次采样且全部失配，从 1 起连续，首次于 800000000001 触发。
- 全局最早触发为 800000000001；`capture` 前 2 后 1，窗口只交付时钟 799999999999..800000000002 四行，边沿前 `q` 依次为 `"1"`、`"0"`、`"1"`、`"1"`。

复现（单核 Linux、CPython 3.11、离线）：

```sh
python3 -I tools/generate_soak_handoff.py fixtures/soak/handoff-1e12.json
python3 -I -m logic_replay.cli --soak-check fixtures/soak/handoff-1e12.json \
    --output run/soak-handoff.json
```

在 256 MiB 进程地址空间限制下，从 CLI 读入到完整报告发布远低于 30 秒（实测亚秒级），内存峰值远低于限制。该耗时承诺仅针对此样例形态，不为所有合法网表给出统一耗时承诺。自动化测试核对上述确切数值与四行窗口，不只测是否正常退出。
