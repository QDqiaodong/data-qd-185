# 故障覆盖排程 v2

使用者为数字逻辑教学测试数据整理人员。v1 把一份向量按给定顺序独立回放；v2 在此之上交付一份有周期预算的排程：从候选片段中选出执行顺序、决定片段之间是否插入复位，并报告哪些指定的固定电平故障确实被这份排程检出。不能把片段各自从初值跑一遍再合并覆盖率——连续执行时触发器不会自动回到初值，故障侧与参考侧的状态差异会跨片段传递或被复位抹去。

入口 `logic-replay --campaign <JSON> --output <JSON>`，与 `--source` 二选一，必须且只能给一个。网表部分（`inputs`/`gates`/`flops`/`outputs`）完全沿用[v1 契约](contract.md)，顶层不允许再出现 `vectors`，改为：

- `fragments`：1..7 个片段，各有唯一 `id` 和 1..8 条向量的 `vectors` 数组。向量格式与 v1 相同（`id`、完整 `inputs` 映射、`expect` 子集），向量 id 只在片段内唯一，不同片段可重名。每个片段在排程中最多使用一次，可以不选；选中的片段内向量必须完整按顺序执行。
- `faults`：1..8 项，每项恰好含 `gate` 与 `stuck_at`。`gate` 必须是已声明的门 id；`stuck_at` 只允许字符串 `"0"` 或 `"1"`；同一 `(gate, stuck_at)` 对不重复。不同故障不叠加，每种故障单独成电路。
- `cycle_budget`：\[0, 1000000\] 的整数，排程的向量周期数加复位成本不得超出它。
- `reset_cost`：\[1, 1000000\] 的整数，每插入一次复位的成本。

## 回放与判定

第一片段免费从网表初值开始（其复位标记固定为 `false`）。之后每两个相邻片段之间可以直接承接，也可以花一次 `reset_cost` 把所有触发器恢复到网表初值；复位本身不执行向量、不观测。参考电路和每种单故障电路各自维护触发器状态：承接时传递自己的边沿后状态，复位时各自恢复同一组初值。单故障在排程的每个向量周期都生效：指定门本周期的输出强制为固定值，其所有后续读者（包括观测输出和触发器 D 输入）都读强制后的值。其余门逻辑、边沿前观测、边沿同时更新与 v1 相同。

一份排程只有在参考电路的所有非通配期望都满足时才可执行；显式期望 `"X"` 仍是严格对账，参考侧有不匹配的排程即使能区分故障也不参与选择。故障检出只在一行写有 `"0"` 或 `"1"` 期望的输出上判定，且要求参考实际值与故障实际值都已知并相反；漏填、`"*"`、期望 `"X"` 或故障侧实际为 `"X"` 都不构成检出。

## 选择与报告

在成本不超过预算的排程中：先最大化检出的不同故障数，再最小化总成本（向量周期数加复位成本）；仍相同则按有序的 `(fragment_id, reset_before)` 序列取字典序最小者，片段 id 按 Unicode 码点排序，`false` 在 `true` 前。选择是全局最优，不是贪心。覆盖不到全部故障不是错误；零覆盖时选出零成本的空排程。空排程也是合法结果，正常出报告。

报告 `schema_version` 为 2，字段：

- `schedule`：获选步骤的有序数组，每项 `{"fragment_id", "reset_before"}`；空排程为 `[]`。
- `total_cost`：总成本（整数）。
- `detected_faults` / `undetected_faults`：两份清单分别按 `(gate, stuck_at)` 排序。每个检出项附 `witness`：最终排程中第一次实际比对到差异的 `fragment_id`、`vector_id`、`output`、`reference_value`、`faulty_value`；同一周期有多个检出点时取输出名字典序最小者。见证必须来自最终排程，不能从别的排列借用。
- `summary`：片段与故障计数、周期数、复位次数、预算、总成本及 `all_faults_detected` 布尔量，与 CLI 标准输出打印的内容一致。

## 校验与失败约定

整个输入（包括最终未被选中的片段）在任何排程计算之前完整校验：未知字段、重复键、越界数量、非法电平、未声明的故障门、重复故障对、非整数预算等都拒绝。非法输入或目标已存在（含符号链接）退出 2，不覆盖旧目标、不留下半份报告；合法输入退出 0 并原子新建报告。JSON 限制与 v1 相同（≤8MB、拒绝重复键与非有限常量）。没有 HDL 解析、硬件访问或随机向量生成，全程离线。
