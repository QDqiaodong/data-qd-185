# 采集恢复与回放包导出 v4

使用者为数字逻辑教学测试数据整理人员。测试台的下发记录偶尔漏记某些已下发的二值刺激，但周期号仍在，独立的输出采集也保留了可信的边沿前采样。本模式在一份从网表初值开始、没有中途复位的短采集上，补出每格输入的实际可能值，并为指定的复核窗口判断能否把一段自包含的回放包交给另一台只会从网表初值启动的测试台。入口 `logic-replay --recover <JSON> --output <JSON>`，与 `--source`、`--campaign`、`--qualify` 互斥，不得搭配 `--approvals`。

## 输入

顶层恰好 `inputs`、`gates`、`flops`、`outputs`、`rows`、`windows`。网表部分完全沿用 [v1 契约](contract.md)，但触发器最多 6 个。

- `rows`：1..256 条周期记录，数组顺序即时钟顺序，不按 `id` 排序。每项恰好 `id`、`inputs`、`observed`：
  - `id` 在整批内唯一。
  - `inputs` 是已声明输入的子集。缺键表示该周期实际下发了 `"0"` 或 `"1"` 但未记下；显式 `"X"` 是原三值逻辑的字面值，不能拆成 0/1。一行至多漏记 3 个输入。不同缺格之间没有预设相等关系。
  - `observed` 是已声明输出的子集，保存可信的边沿前采样。采样缺键不施加任何条件；显式 `"X"` 必须精确匹配。两个映射的显式值只接受 `"0"`、`"1"`、`"X"`。
  - 没有采样的周期仍驱动电路、更新触发器并传递边沿后状态。
- `windows`：0..32 项，每项恰好 `id`、`from`、`through`，`id` 唯一。两个值都是已有周期 `id`，按采集顺序取闭区间；允许重叠，请求互相独立。

## 恢复报告

先枚举所有完整解释：补齐每个缺格、用原网表从初值连续回放，并满足整批全部采样。判定必须是整次采集的：候选值只属于至少一种能到达最后一个采样并满足沿途采样的完整解释；只看当前周期或只验证相邻周期都不够。候选集是逐格的，不承诺不同格的候选可以独立组合。

结构合法且存在完整解释时 `status="consistent"`，按原周期顺序给出 `cycles`：每周期含 `cycle`（0 起）、`id`，以及按输入声明顺序排列的 `inputs`。每个输入格为三者之一：

- `{"input", "status": "recorded", "value"}`：原样记录，含显式 `"X"`。
- `{"input", "status": "recovered", "value"}`：在所有完整解释中该格实际唯一。
- `{"input", "status": "ambiguous", "candidates": [...]}`：多个可能值，按 `"0"`、`"1"`、`"X"` 排。不会用 `"X"` 表示歧义，也不会随机挑一条解释。

不存在完整解释时 `status="contradiction"`，不发布任何恢复值（`cycles` 为空）也不导出回放包；`first_contradiction` 给出按采集顺序首个让截至该行的全部采样无法同时满足的周期 `id`（同时给出 0 起下标 `first_contradiction_index` 便于复算），每个窗口标为 `blocking_reason="capture_contradiction"`。采集矛盾是正常分析结论，不是输入格式错误。

## 窗口交接与回放包

对一致采集逐一处理窗口。以下条件按此顺序检查，首个不满足者成为该窗口的 `blocking_reason`：

1. `window_input_ambiguity`：窗口内所有输入格必须已记录或能唯一补回；歧义格列在 `ambiguous_cells`。
2. `entry_state_ambiguity`：所有完整解释必须在窗口首周期的边沿之前拥有同一份完整触发器状态。即使窗口只观测到一个输出，也不能以该输出相等代替全状态相等；都可能状态列在 `entry_states`。
3. `no_eligible_warmup`：另一台测试台仅用原网表和现有采集的输入，无法从原始初值经一段紧邻窗口的连续预热进入该入口状态。

预热规则：允许零预热，也允许窗口前一段连续周期，逐行不得跳过、重排或填入任意候选值（每格同样必须已记录或唯一补回）。只要求从原始初值执行预热后的边沿前状态等于入口状态，不要求预热起点就与历史状态相等，也不用预热期间的历史输出做断言——预热的行不携带期望。满足条件时选**最短**预热，而不是默认带上整段前缀。

成功时窗口为 `status="handoff"`，含 `entry_state`（按触发器名排序）、`warmup_cycle_ids` 与 `warmup_length`（0 表示零预热）、`window_cycle_ids`，以及 `replay_package`：一个可直接保存为 JSON 交给原 `--source` 的对象。它保留原网表（`inputs`/`gates`/`flops`/`outputs`）与周期 `id`，`vectors` 只含选中的预热行和窗口行；预热行 `expect` 为空，窗口行 `expect` 只拷贝原 `observed`，不会把推算输出冒充采样。回放包不依赖恢复报告或采集文件即可运行。

不能交接时窗口为 `status="blocked"`，带 `blocking_reason`，不返回 `replay_package`。

## 报告形态与确定性

`schema_version` 为 4，顶层 `status`、`first_contradiction`、`cycles`、`windows`、`summary`。`summary` 与 CLI 标准输出打印内容一致，含计数与 `handoffs`/`blocked`。周期与窗口结果保持输入数组顺序；候选值按 `"0"`、`"1"`、`"X"` 输出；只调换 JSON 对象键顺序不改变结果。

## 校验与失败约定

整个输入在分析前完整校验：未知字段、重复键与重复 `id`、越界数量、非法电平、未知网名、坏窗口引用（未知周期 `id` 或反向区间）等都拒绝。非法输入或目标已存在（含符号链接）退出 2，不覆盖旧目标、不留下半份报告，原子新建一次性报告。合法但采集矛盾或部分窗口阻断仍退出 0 并出完整报告。JSON 限制与 v1 相同（≤8MB、拒绝重复键与非有限常量）。全程离线。
