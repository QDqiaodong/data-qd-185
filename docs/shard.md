# 分片归档与整批更正对账 v5

测试台把一次无复位长采集按时钟切成多个连续分片，交给互相独立、不知道前段末态的离线工位。本模式提供两个与 v1–v4 互斥、不接收 `--approvals` 的入口：

- `logic-replay --pack-shard <JSON> --output <JSON>`：工位只看本段完整刺激与期望，产出可归档、可交给中心的分片摘要（归档）。
- `logic-replay --rollup-shards <JSON> --output <JSON>`：中心只使用清单列出的归档（不查找原始刺激或网表文件），像从网表初值顺序回放整批一样出对账与门活动汇总，并为已经消费旧报告的异常队列输出精确的增删改更正明细。

## 工位打包输入

顶层恰好 `stream_id`、`shard_id`、`first_cycle`、`circuit`、`vectors`。

- `stream_id`、`shard_id` 沿用现有向量 ID 字符串规则（非空、≤200 字符）；`shard_id` 在同一批内唯一。
- `first_cycle` 为 0..511 的整数；`first_cycle` 加段内 0 基下标即全批周期号，段覆盖范围必须落在 0..511。
- `circuit` 沿用 v1 网表格式（`inputs`/`gates`/`flops`/`outputs`），但触发器最多 3 个、观测输出最多 16 个；门仍最多 200 个、输入最多 64 个。
- `vectors` 为 1..32 条 v1 格式向量，数组顺序就是本段实际时钟顺序；所有输入必须显式记录，`"X"` 是字面三值（不能拆成两个二值候选），期望中的 `"*"` 与缺期望不参与比较。
- 分片保证从某次运行中连续取出，没有隐藏时钟或复位；打包端不接收前段、历史报告或猜测的入口态。

## 归档格式

归档为带文档化格式标识与校验的单一 JSON 对象：`"schema": "logic-replay-shard-v5"`、`"schema_version": 5`，末位 `checksum` 为对除自身外全部内容做确定性紧凑 JSON 编码后的 `sha256:` 十六进制摘要；任一字节被改动都会在中心校验时失败。

顶层字段：

- `stream_id`、`shard_id`、`first_cycle`、`cycle_count`：段身份与覆盖区间。
- `vector_ids`：按本段时钟顺序排列的向量 ID；与区间一起确定全批向量身份。
- `netlist`：辨认同一网表与确定全批初值所需的最小信息——顺序无关的 `fingerprint`（SHA-256，覆盖所有连接、门类型、触发器初值及输入/观测接口；对象键顺序与输入、门、触发器、观测输出的声明顺序不构成不同网表，门的参数数组按原顺序认定）、排序后的 `inputs`/`gate_ids`/`outputs`、按名排序的 `flop_ids` 与 `flop_initial`。
- `entry_states`：对**每一种完整触发器入口态**给出的独立分支，数量为 3^n（n 为触发器数；无触发器时恰有一个空入口态分支，其 `key` 为空串）。分支按入口态枚举顺序排列，`key` 是按触发器名排序拼接的三值串，如 `"01X"`。
- `summary`：段级计数，供 CLI 标准输出与快速核对。

每个分支的字段：

- `entry`：完整入口态（每个触发器一个 `"0"`/`"1"`/`"X"`）；显式 `"X"` 是一个字面分支，不是两个二值候选，不同入口的结果永远不会被合并成一个可执行分支。
- `end_state`：以该入口态跑完本段后的条件末态。
- `comparisons`：本段明确期望（排除缺期望与 `"*"`）的比较次数。
- `mismatches`：失配明细，每条至少含全批 `cycle`、`vector_id`、`output`、`expected`、`actual`，按周期号、输出名排序。
- `gates`：**全部组合门**（包括未被任何观测输出引用的门）的记录，每门含 `first`、`last`（拼接所需的段边界值）与按本段周期排列的 `values` 三值序列。

归档不保留原始逐周期刺激（任何逐周期输入映射）、可回放向量、可执行网表（门 op/args、触发器 D 连接均不在归档内）或全量逐周期状态/输出轨迹；中心无法仅凭归档再次执行电路，只能按分支查表归并。

## 中心清单

顶层恰好 `stream_id`、`cycle_count`、`base`、`replace`。

- `cycle_count`：1..512，整批周期总数。
- `base`：1..16 个工位归档路径；相对路径以清单文件所在目录为准，绝对路径原样使用。列举顺序不决定时钟。
- `replace`：0..16 项，每项恰好 `shard_id`、`path`；同一 `shard_id` 至多替换一次。

整批校验规则（任一不满足即拒绝，退出 2）：所有归档流 ID 与清单一致、网表指纹相同且接口一致；段 ID 与全批向量 ID 分别唯一；按 `first_cycle` 拼接后恰好覆盖从周期 0 开始、连续无缺无重的 `cycle_count` 个周期。替换是同一 `shard_id` 归档的整体替换，不能新增段或重排时钟；批次、网表指纹、覆盖区间及按周期排列的向量 ID 不得变化（刺激与期望允许更正）。

读回时还会完整校验归档内部一致性：入口态域是否恰好覆盖 3^n 种完整三值组合、门/触发器/观测接口是否齐全且与声明的周期范围一致、失配记录的周期位置与向量 ID 是否对得上、门序列长度与 `first`/`last` 边界是否自洽等。

## 汇总口径

中心从网表初值启动一次，之后每段用各自前缀的真实末态（不复位）在该段归档中选中唯一分支：选择键就是按触发器名排序拼接的当前状态三值串。两份汇总（`old_summary` 用 `base`，`new_summary` 用替换后的清单）都包含：

- `final_state`：全批末态（按触发器名排序）。
- `comparisons`：全批明确期望比较次数；显式 `"X"` 参与比较，缺期望和 `"*"` 不参与。
- `mismatch_count` 与 `mismatches`：失配数与明细（全批周期号、向量 ID、输出名、期望、实际值）。
- `gate_activity`：每门 `values_seen`（实际选中分支在全批所见三值集合，排序输出）与 `known_transitions`。

门活动只统计实际选中的入口态：取各选中分支的门值序列按接缝拼接，相邻周期间仅当两值都是 `"0"`/`"1"` 且不同时计一次 0→1 或 1→0；只要相邻两值之一为 `"X"` 就不计，且不会跨过 `"X"` 去找上一个已知值；全批第一行不算变化，跨段接缝与段内相邻周期同规则。状态追平只代表其后触发器输出可能不再受影响，不代表拼接处的门活动可以照抄。除去不再需要的逐周期轨迹，汇总口径与把相同向量拼成一份 `--source` 输入的回放结果一致。

## 更正明细

`corrections` 以 `(全批周期号, 输出名)` 为键，只描述新旧两份汇总的失配集合差异，按周期号、输出名排序，与文件名和清单列举顺序无关：

- 只在新汇总失配：`{"action": "add", ..., "record": <新记录>}`。
- 只在旧汇总失配：`{"action": "remove", ..., "record": <旧记录>}`（撤销保留旧记录）。
- 两边都失配且期望或实际值变化：`{"action": "update", ..., "old_record": ..., "new_record": ...}`；完全相同（含期望与实际都不变）不发事件。
- 没有替换时两份汇总一致，`corrections` 为空。

更正的影响可能延伸到未被替换的段（中心按真实末态重新选分支，自然传导）；反向更正同样走完整归并，曾经出现的 `"X"` 会在不再被选中的序列中从 `values_seen` 消失。

## 报告形态与失败约定

报告 `schema` 为 `logic-replay-rollup-v5`、`schema_version` 为 5，顶层含 `stream_id`、`cycle_count`、`replacements`、`old_summary`、`new_summary`、`corrections`、`summary`；`summary` 与 CLI 标准输出打印内容一致。归档文件的 `summary` 仅含段级计数。

沿用 v1 的输入文件限制（≤8MB、拒绝重复 JSON 键、非有限常量与未知字段）；越界或错误类型、格式或覆盖不完整的归档、混用不同网表或批次、缺段与重叠、重复替换及身份不符的替换都拒绝（退出 2），不覆盖已有目标（含符号链接）、不留半份结果。数据合法时即使存在失配也出完整报告并退出 0；无需证明归档来自真实工位，也不做防篡改之外的来源证明。全程离线运行。
